# 论文资料采集系统设计

## 目标

建设一套本地、可续跑的 Scrapy 采集项目，为“美国对华舆论传播与话语竞争的历史演变（1949—2025）”发现、取得、核验并整理合法可用的原始资料。系统不得声称绝对穷尽，也不得把摘要、搜索片段或无法核实的正文列作已取得全文。

## 采集边界

- 仅采集公开可访问且允许访问的全文，或用户通过学校图书馆等合法授权方式取得并提供的全文。
- 遇到付费墙、登录验证、访问控制、下载限制或其他访问限制时停止该来源的自动采集，不尝试规避。
- 搜索结果、摘要、目录记录和引用片段仅用于发现候选材料，不进入已取得全文的数据集。
- 每条正式记录的发布日期必须能从来源页面或授权文件核实到年月日；采用页面显示的发布日期，不以事件日期、更新日期或抓取日期代替。

## 方案与模块

采用 Scrapy 作为通用请求、限速、重试、链接跟随和数据管道框架。来源发现与页面采集分开：种子 URL 可来自官方目录、站内搜索、公开搜索服务或人工整理；Scrapy spider 和来源适配器负责解析允许访问的原始发布页。Firecrawl 可作为可选的候选发现或抓取辅助工具，但其返回内容必须回到原始来源核验，不构成正文核验凭据。

模块边界：

1. `discovery` 保存按时期、来源类型、事件、人名、年份和主题词组织的候选 URL 与检索批次。
2. `spiders` 与 `adapters` 处理不同来源的页面结构；新来源应通过适配器扩展，不改变统一记录约定。
3. `policy` 执行域名范围、robots 规则、请求节制和访问限制停止策略；不实现付费墙或身份验证绕过。
4. `evidence` 保存原始 URL、获取时间、响应状态、原始页面或授权文件引用、内容哈希和核验状态，作为审计材料，不导出到正式 Excel。
5. `validation` 只允许通过字段来源核对、日期核对、正文对应性及完整性检查的记录进入正式导出；HTML/JSON 正文还必须能在保存的原始响应中按归一化首尾词序找到；无法确认时保持为候选或待核验状态。
6. `export` 生成仅含九列的 Excel；超出单元格限制的完整正文另存为 UTF-8 文本，并在正文单元格写入唯一相对路径。
7. `progress` 记录时期、来源类别、批次主题、候选/已核验全文/受限/重复数量及未覆盖部分，支持续跑。

## 正式数据与文件

正式 Excel 严格使用以下九列，顺序固定：来源、时间、作者、标题、摘要、关键词、正文、来源链接、重复计数。不得增加说明性字段。

字段规则：来源、作者、标题和发布日期照录来源证据；页面未注明作者时填“未注明”。来源有原摘要时照录；无摘要时依据正文整理并以“据正文整理：”开头。关键词须由正文支持。正文应为与同一来源链接、标题、作者和日期匹配的原文主体，保留段落顺序并排除模板内容，不翻译、改写、拼接或截断。长正文文件名必须唯一对应记录。

内部状态数据库和证据文件可包含核验、批次和错误信息，但不得改变 Excel 的九列限制。按规范未能核实到日、来源受限、正文不完整或正文与元数据无法对应的材料不得进入正式表。

## 去重与重复计数

以规范化后的原始发布链接或平台唯一内容 ID 识别同一材料。唯一材料只保留一行；本次检索发现的重复出现次数写入“重复计数”，不含主记录，未发现时为 0。不同机构各自发布的转载或改写稿分别保存。规范化只用于比较，不改写正式来源链接。

## 分批流程

按 1949—1972、1972—1991、1992—2016、2017—2025 四个时期顺序工作；每个时期再按媒体、政府/广播机构、智库/研究机构/非政府组织、新媒体及中英文研究文献分组。关键事件只用作检索线索，不作为对材料政治性质的预判。

每批执行：生成检索组合与候选 URL；筛选访问许可；采集允许公开的原始页面或导入授权文件；提取字段和正文；逐项核对；去重；将通过核验的记录导出；检查 Excel 列、长正文文件及来源证据；报告实际完成数和仍未覆盖部分。下一批读取进度库，避免无意义重复。只有在检查范围内没有明显新增且访问条件已穷尽时，才能表述为“暂未发现明显新增”，不使用绝对穷尽表述。

## 失败处理

- 网络错误、限流和服务器错误按有界重试处理；持续失败的 URL 记入批次待处理清单。
- 遇到访问限制立即停止该页面的进一步自动尝试，记录受限状态，不收录其摘要作为全文。
- 页面没有年月日、正文为空、正文疑似截断、正文与标题不一致或证据缺失时，拒绝正式导出并保留待核验状态。
- 来源链接和证据链接必须是合法 HTTP(S) URL；正文含 HTML 标签或无法在原始 HTML/JSON 响应中找到时，拒绝正式导出。
- 授权文件导入时保留用户提供文件的来源说明与文件哈希；不得擅自推断授权范围。

## 验证策略

先以公开、结构稳定的政府来源小批次验证完整流程。测试覆盖：九列及顺序固定；来源发布日期缺失时拒绝正式导出；受限页面不成为全文记录；搜索摘要不进入正文；重复链接计数正确；长正文完整外置且正文格路径有效；Excel 与证据清单可相互定位；分批续跑不重复插入唯一材料。测试使用本地 fixture，不对真实站点施加负载。

## 分阶段交付

1. Scrapy 项目骨架、统一记录模型、SQLite 进度/去重状态和证据目录约定。
2. 核验闸门、授权全文导入、九列 Excel 与超长正文导出。
3. 一个政府公开来源适配器和离线 fixture 测试，完成端到端小批次。
4. 逐个增加媒体、智库、广播机构和新媒体适配器；逐批报告覆盖情况。

适配器范围以能合法访问和能可靠核验为准。目标来源的全文不可公开访问时，系统提供候选记录和待授权导入路径，不尝试绕过限制。
